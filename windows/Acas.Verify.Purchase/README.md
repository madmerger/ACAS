# 買掛の同一性確認

`Acas.Verify.Purchase` の件数は添付のシナリオ台帳にあるケースの判定です。到達確認が一致しても、その操作の正常終了や出力の同一性を示すものではありません。

## 正常系の証跡範囲

添付のシナリオ台帳の買掛ケースと、該当する `runs/PL-*-breadth` の画面・論理レコード差分・帳票一覧を確認しました。以下の到達確認は Verify の集計に含まれますが、**正常データで処理を完了するケースはレガシー未実施で対象外**です。台帳にない正常系を Verify の総数に加算していません。

| 正常系 | 関連する到達確認 | 旧版証跡に残っている操作 | 正常系の比較 |
|---|---|---|---|
| 小切手データ生成 | `PL-233` | 処理対象なし。小切手データの生成結果なし。 | レガシー未実施で対象外 |
| 小切手・銀行振込台帳、未決済明細更新 | `PL-234` | 未決済明細を更新するかの確認まで。台帳とレコード差分なし。 | レガシー未実施で対象外 |
| 送金案内印刷 | `PL-235` | 送金案内の画面に到達せず小切手・送金メニューを表示。帳票出力なし。 | レガシー未実施で対象外 |
| 買掛・売掛の期間締め | `PL-236` | 締め前のバックアップ・実施確認まで。締め後のレコード差分なし。 | レガシー未実施で対象外 |

## 実画面の監査

Windows の対話デスクトップで、Release ビルド後に実行します。Python は監査専用の SQLite データを作成するために使用します。スクリプトの実行中は対象アプリを前面に置き、マウスを操作しないでください。

```powershell
.\windows\Acas.Verify.Purchase\Audit-PurchaseUI.ps1 `
  -Application .\windows\Acas.App\bin\Release\net8.0-windows\Acas.App.exe `
  -Fixture .\windows\Acas.Core\Baselines\pl-invoice.json `
  -OutputDirectory "$env:USERPROFILE\acas-pl-uia"
```

買掛のツリーに登録された全ナビゲーション項目と、監査で開く確認ダイアログ・帳票を、実 WPF の UI Automation コントロールビューで検査します。結果は `purchase-uia.json` に保存します。データ入力値、勘定コードなどの業務データ表示は英字ラベル検査の対象外です。この監査はデータや入力の組み合わせによる全分岐を実行するものではありません。
